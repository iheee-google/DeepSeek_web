## 评分标准

| 分  | 含义                                 |
| --- | ------------------------------------ |
| 5   | 有机械校验兜底，改动不可能悄悄破坏它 |
| 4   | 有测试覆盖，边界情况也验证过         |
| 3   | 实现正确，但靠人工检查               |
| 2   | 实现存在，有已知缺口                 |
| 1   | 只有约定，无实现                     |
| 0   | 未开始                               |

## 已知最大差距

按「差距 × 影响面」排序：

1. **内容管线未接通**（1 分）。整个站点目前只有硬编码数据，Markdown 内容还没进入仓库。这是当前最大的单点缺口。67 篇笔记仍在 `/mnt/d/Obsidian/iheee/`，front matter 键名中英混杂。
2. **Service / Runtime 两层为空**（0 分）。依赖方向已用测试锁住，但没有内容可服务。随 D1 一起解决。
3. **无性能断言**。Harness §8.2 要求可验证的性能断言，目前只有人工观察。
4. **部署未与 CI 门禁联动**。CI 变红不阻止 Cloudflare 部署，线上仍会上新。

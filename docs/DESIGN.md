# 设计规范

> 视觉决策的落盘处。技术栈与方向由来见 [`design-docs/core-beliefs.md`](./design-docs/core-beliefs.md)；
> 前端实现细则见 [`FRONTEND.md`](./FRONTEND.md)；原型验收结论见 [`requirements.md`](./requirements.md) §5.5。

## 1. 方向

**「证据剧场」**：真实影像 + 大字号标题压印 + 滚动驱动推进。

冲击力来自**真实影像与内容的密度**，不来自装饰。全站无渐变装饰、无发光、无粒子。

## 2. 已否决的通用方案

以下两类方案被明确否决，不得回流。两者的共同问题是**任何作品集站点都能用**，不构成辨识度。

| 否决对象                                                          | 原因                                   |
| ----------------------------------------------------------------- | -------------------------------------- |
| 暖奶油底（近 `#F4F1EA`）+ 高对比衬线 + 陶土强调色（近 `#D97757`） | 当下生成式设计的头号配色特征           |
| 近黑底 + 单一亮强调色（酸性绿 / 朱红）                            | 同上，且被误当作「高级感」的捷径       |
| 纯网格 + 编号 + 等宽字体的「技术档案馆」                          | 理性但情绪浓度低，达不到要求的视觉冲击 |
| SaaS 卡片套件（同圆角、同柔和阴影、内容切成等大卡片）             | 通用默认，无内容呼应                   |

## 3. 核心机制：百叶窗

首屏机制来自素材本身，不是装饰。

- `scenes/office-vito.jpg` 与 `portraits/vito.jpg` 是**同一场戏的两种裁切**，画面骨架是**横向百叶窗切出的光带**。
- 实现用**一条 CSS mask**（`mask-image` + `mask-size:100% calc(100%/14)` + `mask-repeat:repeat`）复现 14 条横缝，而非 14 个 DOM 节点。理由：DOM 节点方案在切换时要重排 14 个元素，mask 方案只改一个自定义属性。
- 换幕只切横条透明度与轻微合拢，**图片不换位置、不重排**。
- 展开动画用 `@property --slat` 注册为 `<percentage>` 做插值。**必须注册为 `<percentage>`**：注册成 `<length>` 时含百分号的 calc 无法插值，动画静默失效。

## 4. 排版

| 项           | 规则                                                                          |
| ------------ | ----------------------------------------------------------------------------- |
| 中文字体     | Noto Serif SC（正文与标题）/ Noto Sans SC（界面小字）。两字体均为 SIL OFL 1.1 |
| 构建字体     | 构建期按实际字符集子集化为 woff2（24 MB → 134 KB），**不直接引全量 TTF**      |
| 行宽         | 正文默认 < 80 字符                                                            |
| 标题         | 只陈述事实或省略；禁止排比、对仗、「这就是……」式总结、替读者解读、伪造金句    |
| 标点         | 标题可省句末标点（用户 m00625）。正文标点正常                                 |
| eyebrow 标签 | **禁止**标题上方的全大写拉开字距小标签                                        |
| 编号标记     | 只在内容真的是序列时使用                                                      |

## 5. 配色

深棕黑底方案（非纯黑）：

| Token        | 值        | 用途                                             |
| ------------ | --------- | ------------------------------------------------ |
| `--bg`       | `#0b0907` | 页面底。深棕黑，避开「近黑底」反模式             |
| `--bg-raise` | `#141110` | 抬升面                                           |
| `--fg`       | `#f0e9db` | 主文字                                           |
| `--fg-dim`   | `#a89e8f` | 次要文字                                         |
| `--fg-faint` | `#6f665b` | 第三级文字、元信息                               |
| `--gold`     | `#c39a45` | 唯一强调色，只进入证据区（年份、出处、判定标记） |
| `--rule`     | `#2a2521` | 发丝分隔线                                       |

对比度满足 WCAG AA。

## 6. 文案规则（硬约束）

由用户 m00173 / m00178 / m00250 三轮反馈确立，已被结构测试机械校验。

- 界面标题**只陈述事实或直接省略**。
- 禁止：排比、对仗、「这就是……」式总结句、替读者解读、伪造金句。
- 禁止标题上方全大写 eyebrow 小标签。
- 文案尽量带**可核对出处**：首屏每屏右下角标注原文行号或章节，如 `视听语言 · 第 1 个符号 · 第 764 行`。
- **禁止英文 em-dash 与 en-dash**（中文破折号「——」不在禁令内）。

## 7. 反面清单（Pre-Flight）

提交视觉改动前逐条自查：

- [ ] 没有装饰性渐变、发光、粒子
- [ ] 没有「近黑底 + 单一亮强调色」的整体观感
- [ ] 没有同圆角同阴影的卡片套件
- [ ] 界面文案逐句检查：是否在替读者下结论
- [ ] 没有 emoji（用开源 UI 图标替代）
- [ ] 没有英文 em-dash
- [ ] 标题上方没有 eyebrow 标签
- [ ] 大胆只花在一个地方：一个元素做记忆点，周围保持安静

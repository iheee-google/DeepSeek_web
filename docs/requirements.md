# 个人网站项目需求

## 1. 项目定位

搭建一个属于自己的个人网站，集中展示个人经历、项目成果，以及经过筛选的工作和生活笔记。

网站既是个人简历和作品集，也是长期维护的个人内容空间。

## 2. 项目目标

- 让访客快速了解我是谁、做过什么。
- 展示个人项目、负责内容和项目成果。
- 发布工作经验、技术思考和问题总结。
- 发布生活记录，例如电影观后感、阅读笔记和日常思考。
- 建立一个可以持续更新的个人内容归档。

## 3. 目标用户

- 招聘者和潜在合作方
- 对我的工作或项目感兴趣的人
- 朋友及普通访客
- 未来的自己

## 4. 内容范围

### 4.1 个人简介与简历

包括但不限于：

- 个人简介
- 工作经历
- 教育经历
- 技能与关注领域
- 联系方式和外部链接
- 可选的简历文件下载

### 4.2 个人项目

每个项目可以包含：

- 项目名称
- 项目简介
- 要解决的问题
- 我的职责
- 使用的技术
- 项目成果
- 截图或演示
- 项目链接和代码仓库链接

### 4.3 个人笔记

笔记可能包括：

- 工作经验和工程实践
- 技术学习记录
- 问题分析和解决过程
- 电影观后感
- 阅读笔记
- 日常生活中的思考

笔记应支持日期、分类和标签。

## 5. 已确认的首版决策

> 需求、技术栈与视觉方向于 2026-10-11 通过交互确认形成。原 `../personal-website/` 项目已被用户判定为失败作废，本项目从 Day 0 全新重建，不复用其成果。

### 5.1 产品范围

- 首版同时交付个人作品集与个人笔记。
- 页面覆盖个人简介、工作经历、教育经历、技能与关注领域、联系方式和外部链接。
- 项目支持名称、简介、问题、个人职责、技术、成果、截图或演示、项目链接和代码仓库链接。
- 笔记支持日期、分类、标签，内容覆盖工作经验、技术学习、问题分析、电影、阅读和生活思考。
- 首版支持项目与笔记全文搜索。
- 首版支持中文和英文内容与界面。
- **简历内容拆分进网页结构，不提供 PDF 直接下载**（用户 m00152 Q10 决策）。

### 5.2 内容维护与发布边界

- 项目和笔记以仓库 Markdown 文件维护。
- 每项内容通过 front matter 明确标记 `draft` 或 `published`；只有 `published` 内容进入公开构建和搜索索引。
- `./godfather-trilogy-notes-v4/` 已获用户明确授权，作为**旗舰笔记公开发布**（含其 77 张影像素材），版权风险由用户确认承担。

### 5.3 部署与视觉方向

- 网站部署到 Cloudflare Pages。
- 视觉方向确认为**方向 B「证据剧场」**：全屏真实影像 + 大字号标题压印 + 滚动驱动运镜 + 章节式推进。拒绝方向 A「技术档案馆」的纯网格编号方案。
- 首屏主体确认为**作品先行**：以精选项目开场，弱化自我介绍。
- 动效追求高级、明显的动态体验；必须支持响应式布局、`prefers-reduced-motion` 降级，并受性能预算约束。

### 5.7 笔记版式的差异粒度：按主题，不按单篇（硬约束）

用户在 2026-10-12 两次提出，并明确「我懒得说第二次」（逐字）：

> 还有就是我说的每个笔记都可以设计不用的ui效果 这些都要记住，我懒得说第二次

紧接着自我修正了粒度（逐字）：

> 我刚刚发的不够严谨，不同主题的笔记可以有不同ui（比如后面我会补充风骚律师和绝命毒师），技术帖子先保持一致就行

「不用」按其上下文是「不同」的输入笔误（同一要求在旧会话里的原话是「如果你能按照我这一个整篇笔记去做不同的UI设计，那肯定更是加分项」）。这是用户第三次提出该要求，按**已确认的硬约束**落盘，不再当作「加分项」。

**差异的粒度是「主题」，不是「单篇」**：

| 类别                                                                                                        | 版式                                                                                                          |
| ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **主题型笔记**（电影观后感一类）                                                                            | **每个主题一套 UI**。《教父》一套；用户已说明后续会补《风骚律师》《绝命毒师》，各是独立主题，各可有自己的版式 |
| **技术型笔记**（`linuxdo帖子`、`安卓逆向`、`目标检测`、`程序设计`、`工作`、`毕设`、`面试`、`项目`、`AIGC`） | **本阶段先保持一致**：同体裁共用一套版式，不逐篇另做                                                          |

含义与边界：

1. **笔记正文不使用单一模板**。所有笔记套同一套版式，属违反本条 —— 但「按主题分」已经满足要求，不必逐篇分。
2. **体裁是最低粒度，主题是差异单位**。`docs/FRONTEND.md` 已按体裁分了六种版式（`thread` / `glossary` / `longform` / `product` / `essay` / `index`）；技术帖停在这里即可。主题型笔记在体裁之上再分一层，`film`（电影观后感）主题一个主题一套。
3. **笔记页是机制试验场**。用户明确表示 α/β/γ 这类滚动机制「不属于首页，属于跳转到笔记之后」（m00366），并点名喜欢 β。因此笔记页承担实验性版式，首页承担稳定入口。
4. **不得用它来逃避内容**。版式差异必须由内容形态驱动（论坛帖子有楼层、速查表是表、长文有章节脊、产品记录有版本号、电影主题有人物与时间轴），不能只是换配色或换装饰 —— `prototypes/README.md` 已写明三方向原型的差异「不是配色而是机制」。
5. **本阶段的落地范围**：现在只有《教父》一个主题型笔记，所以「每个主题一套 UI」目前只需保证架构上支持多主题，不要求凭空造出第二个主题的版式。

# 个人网站项目需求

## 1. 项目定位

搭建一个属于自己的个人网站，集中展示个人经历、项目成果，以及经过筛选的工作和生活笔记。

网站既是个人简历和作品集，也是长期维护的个人内容空间。

## 2. 项目目标

- 让访客快速了解我是谁、做过什么。
- 展示个人项目、负责内容和项目成果。
- 发布工作经验、技术思考和问题总结。
- 发布生活记录，例如电影观后感、阅读笔记和日常思考。
- 建立一个可以持续更新的个人内容归档。

## 3. 目标用户

- 招聘者和潜在合作方
- 对我的工作或项目感兴趣的人
- 朋友及普通访客
- 未来的自己

## 4. 内容范围

### 4.1 个人简介与简历

包括但不限于：

- 个人简介
- 工作经历
- 教育经历
- 技能与关注领域
- 联系方式和外部链接
- 可选的简历文件下载

### 4.2 个人项目

每个项目可以包含：

- 项目名称
- 项目简介
- 要解决的问题
- 我的职责
- 使用的技术
- 项目成果
- 截图或演示
- 项目链接和代码仓库链接

### 4.3 个人笔记

笔记可能包括：

- 工作经验和工程实践
- 技术学习记录
- 问题分析和解决过程
- 电影观后感
- 阅读笔记
- 日常生活中的思考

笔记应支持日期、分类和标签。

## 5. 已确认的首版决策

> 需求、技术栈与视觉方向于 2026-10-11 通过交互确认形成。原 `../personal-website/` 项目已被用户判定为失败作废，本项目从 Day 0 全新重建，不复用其成果。

### 5.1 产品范围

- 首版同时交付个人作品集与个人笔记。
- 页面覆盖个人简介、工作经历、教育经历、技能与关注领域、联系方式和外部链接。
- 项目支持名称、简介、问题、个人职责、技术、成果、截图或演示、项目链接和代码仓库链接。
- 笔记支持日期、分类、标签，内容覆盖工作经验、技术学习、问题分析、电影、阅读和生活思考。
- 首版支持项目与笔记全文搜索。
- 首版支持中文和英文内容与界面。
- **简历内容拆分进网页结构，不提供 PDF 直接下载**（用户 m00152 Q10 决策）。

### 5.2 内容维护与发布边界

- 项目和笔记以仓库 Markdown 文件维护。
- 每项内容通过 front matter 明确标记 `draft` 或 `published`；只有 `published` 内容进入公开构建和搜索索引。
- `./godfather-trilogy-notes-v4/` 已获用户明确授权，作为**旗舰笔记公开发布**（含其 77 张影像素材），版权风险由用户确认承担。

### 5.3 部署与视觉方向

- 网站部署到 Cloudflare Pages。
- 视觉方向确认为**方向 B「证据剧场」**：全屏真实影像 + 大字号标题压印 + 滚动驱动运镜 + 章节式推进。拒绝方向 A「技术档案馆」的纯网格编号方案。
- 首屏主体确认为**作品先行**：以精选项目开场，弱化自我介绍。
- 动效追求高级、明显的动态体验；必须支持响应式布局、`prefers-reduced-motion` 降级，并受性能预算约束。
- 主题默认跟随系统，并提供浅色/深色切换。

### 5.4 前端实现审批闸门

- 在正式构建 Astro 前端之前，必须先交付一个可在浏览器直接打开的独立 HTML 原型。
- 原型需体现首屏冲击、滚动驱动运镜、作品先行结构、双语切换、明暗切换、响应式布局和降级策略。
- 只有用户确认原型效果后，才允许实现正式 Astro 页面和业务组件。

#### 界面文案硬规则（由用户 m00173 / m00178 / m00250 三轮反馈确立）

用户三次否决的根因都是**文案**而非方案：`22 岁。整理了 96 年。`、`两条线的长度差，就是这个网站的全部内容。` 一类句子被判定为「模板化」与「AI 味太浓」。

- 界面标题**只陈述事实**，或直接省略。
- 禁止排比、对仗、「这就是……」式总结句、替读者解读、伪造金句。
- 禁止在每个标题上方加全大写 eyebrow 小标签。
- 文案尽量带**可核对的出处**：首屏每屏右下角标注该句在原文的行号或所属章节（如 `视听语言 · 第 1 个符号 · 第 764 行`）。

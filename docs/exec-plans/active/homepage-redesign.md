## 1. 为什么要重做

2026-10-12 用户看了现首页后说（逐字）：

> 首先这些都不适合首页，我认为跳转到这个笔记的才是这个样子的（我很喜欢 β 不知道旧会话干什么了，为什么把首页设计成这样

现首页把**一篇笔记**（《教父》三部曲的百叶窗影像）当成了整个站点的门面。这与用户 2026-10-11 自己给出的两条回答直接冲突：

| 用户回答（seq 381，逐字）                                | 与现首页的关系                     |
| -------------------------------------------------------- | ---------------------------------- |
| 第 2 条：「《教父》只是我写的一篇笔记而已。」            | 一篇笔记成了整站首屏               |
| 第 12 条 `b`：《教父》= **笔记栏目的旗舰条目**（B 选项） | 现首页把它抬成与「项目」并列的主角 |

同时，`requirements.md` §5.5 原先记录的「用户已在看过三个方向原型后确认选定 γ」经逐条核对全部用户消息后确认**从未发生**（该节已改正）。也就是说：现首页不仅选错了内容，连"这是用户选的"这个前提本身也是假的。

用户对"首页该怎么做"的选择是：**先做几个可打开的实物，看实物再定。**

## 2. 首页需要回答的问题

用户第 7 条回答明确说了访客是谁：

> 怎么说呢，你自己当做网友，而我是网站的主人，你觉得用什么内容去呈现好一点？网友不一定是招聘者啊。

所以首页**不以招聘流程为中心**。它要回答的是：

| #   | 问题                     | 谁在问       |
| --- | ------------------------ | ------------ |
| 1   | 这个人是谁、做什么的     | 任何访客     |
| 2   | 他做过什么、会做什么     | 网友、招聘方 |
| 3   | 还有什么可看的、从哪进去 | 愿意停留的人 |
| 4   | 怎么联系                 | 招聘方       |

## 3. 三个候选方向

**三个方向的差别是"首页把什么放在第一位"，不是配色。** 造型语言整体共用 `prototypes/assets/home.css`，差异只在结构。

### A「一条线」 —— 第一位是时间

首屏是大字姓名 + 一条**按真实时间比例**绘制的横尺：`2022.09` 在左端、`现在` 在右端，中间刻度按真实月份定位（共 49 个月），间距就是真实的时间间隔，不是均分。实心点＝月份已知，空心点＝只知道年份。

- 首屏的视觉重量压在字号与刻度上；影像只在《教父》那一段全出血出现一次。
- 页面主体是记录列表，每一条都可回到简历或笔记的原文。
- 记忆点是那条**真的**尺子：`--t` 与刻度标签的一致性由 `tests/structure/layout.test.ts` 机械校验。
- 适合的前提：这个人的价值主要在"持续做了多久"。若不成立，这一页会显得单薄。

### B「一件件」 —— 第一位是问题

首页不讲"我是谁"，讲**四件具体的事**（分类、溯源、并发、成本）。每条从事本身的开场：先给一个真实的技术处境，再给做法，再给可核对的结果。

- 首屏第一句话是一个技术问题（`报关单证 有六种类型。`），不是自我介绍。名字与身份固定在顶栏。
- 强调色只出现在"结果"的数字上，问题与做法保持普通文字色，于是强调色有了明确语法。
- 没有卡片、没有边框、没有阴影；条目之间只有一条发丝线。
- 记忆点是**开场那句具体的话**。
- 风险：访客如果想知道"这人是谁"，需要读几条才拼得出来。缓解方式是顶栏与最后一屏。

### C「一堆」 —— 第一位是体量

首屏是全部 67 篇笔记按**真实行数**排成的轮廓，不叙述。954 行的 `apk 签名` 是那条贯穿全宽的红色横条，14 行的 `Selective Search` 是一小截。条长就是数据，`--w = 行数 / 954`，全库共用一把尺子。

- 不按统一模板排列：`目标检测` 的树（6 条主干 + 8 篇知识点）、`linuxdo帖子` 的 8 根柱、`程序设计` 的 18 条分组短条，各按自己的形状画。
- 首屏只有一个数字（`10,254 行`）与一行必要的锚点。
- 记忆点是**页面尺寸即数据**。
- 风险：这一页偏"资料馆"，情绪浓度低；且笔记正文尚未接入仓库（技术债 D1），现在只能画骨架。

## 4. 三案共用、不参与比较的部分

放在这里是为了让用户的选择**只关于结构**，不必同时重新裁定配色。实现落在 `prototypes/assets/home.css`。

| 项       | 取值                                                                              |
| -------- | --------------------------------------------------------------------------------- |
| 字体     | Noto Serif SC（标题与长文）/ Noto Sans SC（界面与元信息），两字体 SIL OFL         |
| 底色     | `#FFFFFF` 纸白；分区用 `#F1F1EF` 冷中性灰白一档                                    |
| 主文字   | `#14110F`；次要 `#57534D`；三级 `#8B8781`                                          |
| 唯一强调 | `#D4370F` 朱红，只进入状态与交互（当前时刻、最长的一篇、焦点环）。**不是装饰色**   |
| 发丝线   | `#DEDDD8`                                                                          |
| 字阶     | `clamp()` 三档：display / h2 / lead；`letter-spacing` 为负值，字号越大越紧          |
| 动效     | 只动画 `transform`/`opacity`/`scale`；进入用 `cubic-bezier(.22,1,.36,1)`           |
| 文案     | 只陈述事实；无排比、无「这就是」总结、无伪造金句、无 eyebrow、无 emoji             |
| 图标     | Lucide 内联 SVG（ISC）                                                             |
| 降级     | `prefers-reduced-motion: reduce` 时保留透明度与颜色过渡，移除位移、缩放与揭幕      |

**配色依据**：用户 2026-10-12 明确要求「尽量不要暗色系的」（m00695），此前那版深棕黑配色（`#0B0907` + `#C39A45`）随之作废。选朱红而非金色，是因为浅底上金色对比度不足；朱红同时满足"单一强调色"与 DESIGN.md 的反模式清单。

# 设计文档索引

本目录存放架构与设计层面的信念、约束与实测结论。每份文档标注**验证状态**，避免把推测当事实。

| 文档                                                       | 内容                                                                     | 验证状态                                         |
| ---------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------ |
| [`core-beliefs.md`](./core-beliefs.md)                     | 智能体优先的操作原则、技术栈五项结论、视觉方向与冲击力来源、关键架构约束 | 已确认（用户交互确认，非推测）                   |
| [`animation-capabilities.md`](./animation-capabilities.md) | 浏览器动画能力边界：可做什么、6 条写法约束、reduced-motion 处理          | **已实测**（Chromium 153.0.8010.12，附复跑脚本） |

## 阅读顺序

1. 先读 `core-beliefs.md` 的「智能体优先的操作原则」与「已确认的技术栈」两节——这是所有其它决策的前提。
2. 涉及动效、过渡、形变、滚动驱动动画的实现前，**必读** `animation-capabilities.md` 的「写法约束」一节；违反其中任何一条，动画会**静默失效**（不报错、不动画）。
3. 涉及目录职责与依赖方向，读仓库根的 `ARCHITECTURE.md`。

## 与其它目录的关系

- 产品层面的范围与边界在 `docs/requirements.md`。
- 前端规范（组件、样式、动效落地细则）在 [`../FRONTEND.md`](../FRONTEND.md)。
- 设计规范（版式、排版、配色）在 [`../DESIGN.md`](../DESIGN.md)。
- 自动化门禁与框架判定在 [`../CI.md`](../CI.md)。

## 新增设计文档的约定

- 文件名用小写连字符（`animation-capabilities.md`），不用中文名。
- 每份文档必须有「验证状态」标注：`已实测` / `已确认` / `待验证` / `推测`。**推测类内容必须显式标注**，否则会被后续会话当作事实引用。
- 若文档记录了实测数据，必须同时给出可复跑的脚本路径，否则数据会随时间失效且无法复核。
- 每份文档末尾维护「变更历史」表。

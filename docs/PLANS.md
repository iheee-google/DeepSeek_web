# 计划规范

> 执行计划是一等工件（Harness §2.2）。活跃计划、已完成计划、技术债全部版本受控，
> 使智能体无需外部上下文即可接续工作。

## 1. 目录

```text
docs/exec-plans/
├── active/               # 活跃计划，含进度与决策日志，提交入库
├── completed/            # 已完成计划，归档
└── tech-debt-tracker.md  # 技术债清单
```

## 2. 何时用临时计划，何时落盘

| 情形                                 | 做法                                   |
| ------------------------------------ | -------------------------------------- |
| 单文件小改、错别字、一次依赖升级     | 不需要计划文件，直接改                 |
| 跨多文件、有未知数、预计超过一次会话 | **必须**写 `active/<name>.md`          |
| 需求澄清、技术栈确认、多轮交互决策   | 必须写，且决策逐条落盘（Harness §2.2） |

判据：**如果一个新会话的智能体只读仓库，能否知道这件事做到哪了、为什么这么做？** 不能，就该落盘。

## 3. 模板

```markdown
# <计划名>

| 项       | 值                        |
| -------- | ------------------------- |
| 状态     | 进行中 / 阻塞 / 已完成    |
| 创建日期 | YYYY-MM-DD                |
| 负责人   | 智能体 / 用户             |
| 关联     | 需求章节、issue、其它计划 |

## 目标

一句话说清完成后世界变成什么样。

## 拆解

- [ ] 步骤一
- [ ] 步骤二

## 决策日志

| 日期 | 决策 | 理由 |
| ---- | ---- | ---- |

## 进度日志

| 日期 | 进展 | 阻塞 |
| ---- | ---- | ---- |

## 验证

怎么证明做完了（命令、截图、用户确认）。
```

## 4. 硬规则

- **决策必须写理由**。「选了 A」是无效记录，「选 A 不选 B，因为 C」才是。
- **进度日志按时间追加，不重写历史**。计划转向时新增一行说明转向原因，不删旧行。
- **实测数据必须附可复跑的命令或脚本路径**，否则数据失效后无法复核。
- 计划完成后 `git mv` 到 `completed/`，并在文件头加归档说明（完成日期、最终结论）。
- **未完成的计划不得移入 `completed/`**。

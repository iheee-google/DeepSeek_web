# 强化角色标注、补全简称映射与全文页人物卡

## Goal

修复全文人物标注和图片查看器的三个可见交互问题，并纠正人物详情的导航方向：

1. 全文中的角色名称默认态需要足够突出，用户不依赖 hover 才能发现它是可交互的人物入口；
2. 在不误标普通词、演员名、复合人名和历史同名的前提下，补齐原文中可唯一归属的角色简称/缩写；
3. 图片查看器点击关闭、Escape、遮罩关闭后应立即进入关闭完成状态，不再让用户等待当前 280ms 退场计时器；
4. 点击全文角色名称后，人物介绍直接在当前 `notes.html` 内打开，不跳转首页人物大全、不再经过确认弹窗；关闭人物卡后仍留在原文、恢复原阅读位置和焦点。

## User value

用户能在长篇全文中快速识别可跳转的人物名称，看到熟悉的简称也能进入正确的人物介绍；查看图片或人物卡后能继续原位置阅读，不被跨页导航和延迟遮罩打断。

## Confirmed repository facts

- `notes.html` 通过 `archive.sections[].html` 注入 `#noteContent`，当前用 TreeWalker 在单个文本节点内生成原生 `button.person-mention`。
- 当前 `.person-mention` 默认态约为低对比色、约 1px 下划线和极浅背景；截图 `e46ee03a-615c-424f-a93e-243cb7b612df.png` 中的“维托”“索洛佐”等文本没有标注，已配置的“桑尼”也不够醒目。
- `scripts/build-content.cjs` 维护 44 条人物规则并生成 `person.mentions`；现有完整名和少量别名已通过构建期冲突校验，但短名尚未形成独立的边界/反例契约。
- 原文存在可审查的简称使用，例如“老维托”“维托”“麦克”“桑尼”“汤姆”“凯”“康妮”“卡洛”“索洛佐”等；其中部分短串可能出现在其他人名或普通词中，不能批量加入。
- `index.html` 的 `characterData` 和 `readerHtml()` 已经从 `archive.people` 生成完整人物介绍；当前 `morphPerson()` 依赖首页人物卡片并打开首页 reader。该实现不能直接被全文页调用，因为它绑定首页 DOM、首页滚动和首页关闭焦点。
- 当前旧版角色标注确认动作会生成 `index.html?person=<id>#characters`，并通过 `history.state` 做跨页返回恢复；这条行为偏离用户修正后的要求，新流程不得再导航到首页。
- `assets/js/image-viewer.js:273–303` 的 `closeViewer()` 会加入 `.is-closing`，并用 `setTimeout(..., 280)` 才调用 `dialog.close()` 和移除 `body.image-viewer-open`；`assets/css/image-viewer.css` 同时播放 `.28s` 退场动画。全屏模式会调用 `document.exitFullscreen()`，但顾问确认当前明确的逻辑关闭等待来源是 280ms 计时器。
- 当前项目正式验收为桌面 `1920×1080`、`1440×900`、`1024×900`；窄视口仅保留既有防回归，不构成移动端交付。

## Research findings

- GOV.UK、MDN、Home Office 和 W3C 的公开链接指南共同强调：内联交互文本默认应有清晰的对比色和可见下划线，不能只靠 hover 或颜色；focus 需要独立、高对比的背景/轮廓反馈。
- shadcn 的公开文本链接模式保留下划线，并用 hover 强化、`focus-visible` ring 区分键盘焦点；这里只借鉴状态层级，不引入 React/Radix。
- 公开 Dialog/Alert Dialog 模式强调标题、说明、关闭动作、焦点约束和 Escape；全文页继续使用原生 HTML/CSS/JavaScript，不复制外部实现。
- 研究页面不是运行时依赖，不复制外部代码，不增加 CDN 或组件库。

## Requirements

### A. 标注可见性

1. 纳入映射的 `button.person-mention` 在默认态就必须同时具备至少两种可识别线索：与正文有足够对比的角色强调色，以及稳定可见的下划线或底部标记；不能只在 hover/focus 时显示。
2. hover、active、focus-visible 继续提供更强反馈；focus-visible 必须不依赖颜色单一变化，并且不能裁切、改变正文字符或强制整段单行。
3. 视觉增强保持 family–power 视觉语言，不给每个人物随机分配颜色，不使用高密度彩色胶囊，不引入外部图标或依赖。
4. 标注按钮仍是原生语义控件，正文 `textContent`、链接属性、稳定 block ID、目录/hash、搜索文本和重复初始化行为保持不变。

### B. 简称/缩写映射

1. 由生成器维护受控简称表，映射到现有稳定 `person-*` ID；未知、冲突或标题变化必须在构建期失败，不能静默跳错。
2. 先审计实际全文文本节点和上下文，再加入可唯一归属的简称；候选至少覆盖截图中的“维托”“索洛佐”，并审查“老维托”“麦克”“汤姆”“凯”“康妮”“卡洛”等候选。
3. 长名称优先只用于同一位置的匹配顺序；简称规则必须额外声明复合词/人名保护或排除上下文，不能依赖最长匹配解决所有歧义。允许读取同一语义块的连续文本来识别跨 `strong`/`em` 的保护词，但只修改实际命中的原文本节点，不合并节点。必须验证“麦克”不会侵入“麦克拉斯基”“麦克莱伦”“麦克白”，“汤姆”不会侵入“汤姆逊”或演员名，“凯”不会侵入“凯恩斯齐格”等反例。
4. 不标注归属不明或处于组织/家族语境的姓氏、演员姓名、泛称、历史原型和无法唯一归属的单字/短串；在全文上下文中明确唯一指向人物的姓氏可以标注；`person-43` 的历史同名排除必须保持。
5. 每个新增简称必须有构建校验和浏览器验收：目标 `data-person` 正确、标注文本与源文本完全一致、匹配不跨 `strong`/`em`/链接/code/图片替代文字或控件。
6. `person-27` 两位人物的新增简称（若审计确认安全）必须同时指向 `person-27`，不得拆成两个目标。

### C. 全文页人物介绍

1. 点击 `.person-mention` 后直接在当前 `notes.html` 打开页面级人物详情 panel/dialog，不改变 `location.href`、hash、query 或浏览历史；不再显示“是否跳转”的确认弹窗。
2. 人物详情必须消费 `archive.people` 的同一条人物记录和 `person.html`/`person.text`/`person.image` 数据，不在 `notes.html` 手写或复制人物介绍正文；共享的渲染逻辑可抽取为无框架本地模块，页面状态管理仍可路由内维护。
3. 详情层显示人物完整标题、别名/演员元信息、肖像和现有人物介绍正文，使用独立 DOM ID，不能与全文原始 heading/block ID 重复；图片继续接入现有全局图片查看器。
4. 详情层打开时锁定背景滚动并设置背景 `inert`，初始焦点进入关闭控件或详情操作区；支持鼠标、Enter/Space、Escape、遮罩关闭和 Tab 循环。
5. 关闭详情层后，`notes.html` 的 hash、scroll anchor、阅读位置和正文状态不变，焦点使用 `focus({ preventScroll: true })` 恢复到触发的人物标注；快速关闭后重新打开另一人物不能显示旧内容或被旧退出计时器覆盖。
6. 人物详情内的图片查看器 Escape 必须先关闭图片查看器，再由下一次 Escape 关闭人物详情；不留下 inert、滚动锁或 `is-closing`。
7. 旧的首页 `person` 深链和 `noteCharacterReturn` 逻辑先检查调用方；新流程不得生成首页深链。无其他调用方时只删除直接为旧流程服务的死代码，不能破坏已有的合法首页 URL 兼容行为。

### D. 图片查看器关闭

1. 点击关闭按钮、Escape 或遮罩关闭后，关闭操作在下一帧/明确短边界内完成：`dialog.open`、背景锁定和不可见退场层不能继续阻塞阅读；不能继续固定等待 280ms 才解除页面。
2. 正常动效可以保留非阻塞的即时退出反馈，但逻辑关闭、滚动恢复和焦点恢复不能依赖动画计时器或全屏 Promise 完成；原生全屏退出可以异步完成，但应用层 `dialog`、自身滚动锁和 closing 状态必须即时完成；`prefers-reduced-motion` 必须即时完成。
3. 处于真实全屏、模拟全屏、嵌套阅读弹窗和快速关闭后立即重开时，不能留下 `.is-closing`、滚动锁、错误 fullscreen 状态或旧的关闭回调；新打开必须取消旧关闭状态。
4. 保留图片比例、缩放锚点、四边可达、动态图片装饰、图片查看器与人物详情的 Escape 互斥关系。

## Out of scope

- 不修改原始 Markdown 的可见文字、标点、顺序或人物介绍正文；允许生成器增加受控映射元数据。
- 不把所有姓氏、泛称、演员名或不确定短称强行标注；只有全文上下文能唯一归属人物的姓氏/简称才进入映射。
- 不重做首页人物卡片、全文版式、搜索系统或 Cloudflare 发布边界。
- 不引入 React/Radix、外部 CDN、通用 tooltip 库或新的图片查看器。
- 不做移动端专门设计；既有窄视口图片查看器检查只用于防回归。

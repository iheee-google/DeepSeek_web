# Design: 档案站系统化文字排版

## Boundary

本任务只调整首页 `index.html` 与全文页 `notes.html` 的文字布局和对应桌面回归，不改变原始 Markdown、生成器、生成数据、图片、搜索定位、模块信息架构、业务交互或 Cloudflare 配置。正式视觉目标为 1920×1080 与 1440×900，并用 1024×900 作为桌面边界验收。移动端（手机/平板）不新增布局、不做移动端视觉调整、不新增移动端截图或验收；现有套件的历史 `390×844` 回归继续保留，但不构成移动端交付。

## Problem Model

排版问题不是某一个标题字号错误，而是三个因素叠加：

1. 显示标题使用手工 `<br>`，但断点两侧没有语义行组，父列变窄时浏览器会在预设断点内部再次分行。
2. `.section-header`、`.notes-portal-card` 和 `.notes-hero` 的列宽、最小列宽、内边距与显示字号共同决定标题可用宽度；较窄桌面下共享 section header 已复现短词单独成行。
3. 说明文字使用固定最大行宽，全文页在 1440 下可出现末行过短；正文、元信息、列表和表格需要分别使用其内容适合的阅读宽度，不能用一个全局规则覆盖。

用户截图的具体来源尚未被证明；首页入口卡和全文页首屏使用同一标题，二者都纳入测量和验收。

## Research-derived Constraints

研究只提炼公开模式，不复制外部代码，也不引入外部运行时依赖：

- `shadcn/typeset` 将渲染内容的排版收敛为基础字号、行高和块间距三个节奏变量；本项目采用同样的少量共享变量思路，而不是逐个模块微调字号。
- Taste Skill 的类型规则要求桌面主标题控制在两行内，较长陈述/引文保持 statement 层级并允许约 2–3 行；大字号使用收紧字距、平衡换行和明确行组，不能把所有文本压成一行。
- Transitions.dev 的 `texts-reveal`、`text-morph` 和 `panel-reveal` 区分文本行进入、文本内容替换和面板展开；本项目只借鉴状态边界与 reduced-motion 处理，不复制其 `t-*` 代码。
- beUI 的文字动画保留最终文本作为可访问内容，动效只表现揭示过程；本项目的引文展示也必须保留完整可读文本。
- Rare UI、Beautiful UI 和 Variant 的相关页面存在付费或动态抓取限制，不能据此声称完成源码审计；它们只作为交互构图参考。`getdesign.md` 的公开页面也未稳定返回内容，不作为实现依据。

研究入口记录：`https://ui.shadcn.com/docs/typeset`、`https://transitions.dev/`、`https://beui.dev/`、`https://www.rareui.com/`、`https://www.beautifului.dev/`、`https://www.variant.com/`、`https://getdesign.md/`、`https://www.tasteskill.dev/`，以及公开的 `design-taste-frontend` skill。它们只提供参考原则，不成为运行时依赖或代码来源。

## Typography System

### 1. Display titles

- 将首页规则、时间轴、人物、史实、符号、结尾及两条全文入口标题的手工断点表达为语义行组（例如 `.title-line`），而不是让裸文本和 `<br>` 共同承担布局契约。
- 行组只用于确实有设计断点的显示标题；不对正文、列表、表格或所有中文文本全局设置 `white-space: nowrap`、`word-break: keep-all` 或固定像素高度。
- 桌面正式宽度保留设计行组；较窄桌面通过共享标题规则和布局降级保证行组有足够可用宽度，必要时让标题区域提前堆叠或降低显示字号，而不是让行组内部产生孤字。
- 统一显示标题的字号、字距、行高和最大测量宽度变量；已有历史标题的结构化 span 作为可复用模式，不复制一套独立例外。
- 全文页生成章节标题时保留括号内容为不可拆分的标题组，并调整主标题组的字号上限；这只改变显示层的断行，不改变 heading 的文本、目录或稳定 ID。

### 2. Header and card layout

- 让 `.section-header`、`.timeline-head`、`.notes-portal-card` 和 `.notes-hero` 的标题列使用可收缩的 `minmax(0, 1fr)` 语义列，并根据测量结果选择桌面降级阈值；保留 1920/1440 下的并列构图。
- 入口卡和全文首屏的标题可用宽度、右侧说明和统计信息分别控制，不能由右列最小宽度挤压标题列。
- 说明文字保持自然换行与受控阅读宽度，避免末行只有无意义的短尾；不为达到固定行数删改文案。

### 3. Body copy and metadata

- 正文使用适合长文阅读的最大行宽和行高，标题、kicker、统计数字、元信息和表格继续使用各自层级，不将正文的行高放大到标题或将标题规则套到表格。
- 标签、来源和元信息等短内容在容器允许时保持一行；空间不足时按分隔符或完整词组换行，不拆成孤立字符。
- 对全文页章节标题、列表、表格、目录和说明文案只修复已测量的溢出、裁切或明显失衡；不改变原文结构和稳定锚点。

### 4. Quote and punctuation display

- 引文主显示不是标题，也不强制一行；短引文可以一行，较长引文按语义分句形成 1–3 个平衡行组，行组内部不得出现孤立单字。1–2 行标题和 1–3 行引文是设计目标，不得通过裁切、隐藏、省略号或过度缩小字号硬凑；完整内容和可读字号优先。
- 首页引文大字层采用按稳定引文 ID 定义的展示层映射，省略装饰性逗号、句号并把分句边界转成视觉换行；源 Markdown、`archive.js`、`notes.html` 完整正文和可访问文本保留原标点，不使用通用删标点函数。
- 不使用全局正则删除标点，不处理正文、列表、表格或搜索源文本；只允许在引文主显示组件内做明确、可审计的展示转换。
- 引号装饰使用显式的 `quote-open`=`“` 与 `quote-close`=`”`，两者使用同一字号、同一容器网格和可测量留白，不通过旋转同一个开引号伪造闭引号；装饰标记对辅助技术隐藏，展示映射与完整原文只向辅助技术暴露一个中文版本，避免视觉文本和隐藏文本重复朗读。
- 引文中文、英文原文、来源和解读保持层级分离；不把所有内容合并到同一超大字号行中。

## Runtime and Compatibility

- 保留现有原生 HTML/CSS/JavaScript 结构、Lucide 图标、IntersectionObserver reveal 和 reduced-motion 行为。
- 不新增字体 CDN、框架或依赖；排版必须在当前本地字体栈和不同 CJK 字体度量下保持安全边界。
- 不把截图中的当前环境表现直接升级为跨平台事实；测试断言优先验证语义行组、容器几何、无横向溢出和可见性，像素值只用于桌面截图复核。

## Verification Design

1. Playwright 在 1920×1080、1440×900、1024×900 加载 `/` 和 `/notes.html`，等待 `document.fonts.ready` 与 reveal 稳定后检查主要显示标题；不新增或验收移动端排版视口，现有历史窄视口回归仍按既有契约执行。
2. 主要标题使用文本 `Range.getClientRects()` 检查实际行盒，而不是只检查 `.title-line` 元素宽度；每个语义行组应为可见单行且不超出标题容器，标题和说明容器不得有横向 scroll overflow，页面不得出现水平滚动条。
3. 对全文页说明、首页 section intro、动态规则/时间轴/人物/史实/符号标题做可见性和容器边界检查；正文断行不固定成脆弱的字符数。
4. 引文回归覆盖全部 9 条记录和最长文本，逐稳定 ID 比较展示映射与原文，只允许省略批准的逗号和句号，其他字符及顺序不变；同时检查真实开闭引号、主引文 1–3 行的语义行组、完整原文不变、来源/解读仍可见、快速连续切换后的最终中文/英文/来源/解读状态，以及 reduced-motion 状态。
5. 记录每个桌面视口的实际 CSS `innerWidth`/`innerHeight`、DPR、声明的 `font-family`、`document.fonts` 状态、可确认的实际字体、字号和标题行盒；无法从浏览器确认实际字体时如实标注，1920 屏幕分辨率不直接当作 CSS viewport。引号以同一主引文容器为基准检查左右镜像留白，并结合截图做视觉复核。
6. 1920×1080 和 1440×900 截图复核布局层级，1024×900 做桌面边界检查；不新增移动端截图、移动端排版调整或移动端验收。
7. 保持现有 6 项 Playwright 行为回归（其中 1 项历史测试使用 390×844），新增排版检查只运行桌面视口，并运行内容构建、JavaScript 语法检查和 `git diff --check`。

## Trade-offs and Rollback

- 选择语义行组和共享排版变量，会改动若干静态标题标记，但能阻断同类标题在不同容器中重复出错；不选择逐个标题增加宽度/字号补丁。
- 选择较窄桌面提前堆叠标题与说明，可能减少部分宽度下的并列构图，但优先保证阅读层级和文案完整性；1920/1440 的并列构图保持不变。
- 回滚只需恢复 `index.html`、`notes.html`、对应测试和产品设计记录；不影响内容源、生成数据、图片、构建和部署配置。

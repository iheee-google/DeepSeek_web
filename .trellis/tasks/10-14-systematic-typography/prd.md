# 系统化修复档案文字排版

## Goal

统一首页 `/` 与完整全文页 `/notes.html` 的中文标题断行、显示层级、列宽、正文行宽和展示标点，消除单字孤行、标题被容器意外二次折行、显示文字拥挤、引号不成对和模块间排版失衡；保留原笔记内容、稳定链接和现有交互。

## Background Facts

- 当前项目是原生 HTML/CSS/JavaScript；首页排版集中在 `index.html` 的内嵌样式，全文页排版集中在 `notes.html` 的内嵌样式。
- 用户提供的截图显示标题“把所有沉默 / 还给正文”被实际渲染为“把所有沉 / 默 / 还给正文”，出现单字孤行和设计断点失效；截图尚不能仅凭画面确定来自首页入口卡还是全文页首屏，两条路径都必须实测。
- 首页 `index.html:969-972` 与全文页 `notes.html:143-150` 都使用相同文案和硬编码 `<br>`。
- 首页 `.notes-portal-card h2` 在 `index.html:780-782`、`837-844` 使用标题宽度限制、双列网格、右列最小宽度和大字号；这些是待核对的约束，不预先认定为截图根因。
- 全文页 `.notes-hero` 与 `.notes-hero h1` 在 `notes.html:47-51` 使用大字号、双列网格和硬编码 `<br>`；截图字号更接近全文页标题，因此该路径需要优先测量。
- 首页多个模块标题也使用手工 `<br>`：规则、时间轴、人物、史实对照、符号和结尾模块（`index.html:959`、`985`、`1020`、`1035`、`1045`、`1056`）；不能只修截图中的一个标题。
- 当前工程规范要求保留原文、稳定 ID、桌面回归、reduced-motion 和完整全文入口；本任务不修改原始 Markdown、生成器、图片或业务交互。
- 用户补充确认：即使在 1920×1080 桌面屏幕上，标题也会出现“默”单独成行；因此正式桌面验收必须覆盖 1920×1080 与 1440×900，不能只验证较窄视口。
- 在当前 Linux/Chromium、等待字体加载完成后，1440×900 与 1024×900 下两条“把所有沉默 / 还给正文”标题均保持两行；这与用户在 1920×1080 的实际表现不一致，说明字体度量、布局上下文或线上截图环境仍需用桌面截图和语义行组共同验证，不能把本地一次测量当作充分证据。
- 当前测量还确认共享 section header 和全文页说明存在列宽/行宽风险；这些风险纳入桌面系统修复，但不扩展为移动端开发。
- 现有 `tests/desktop-smoke.spec.js` 没有主要标题的行盒、溢出、单字孤行或正文说明行宽断言；本任务需要在不把内容断行写死成脆弱像素值的前提下补充可观察的几何回归。
- 第八章源文案在 `content/godfather-trilogy-notes-v4.md:720-756` 使用成对英文引号包住英文台词，中文译文保留正常逗号和句号；`index.html:1003` 与 `index.html:1011` 却都渲染同一个开引号 `“`，右侧通过 `transform: rotate(180deg)` 伪造闭引号，存在字形和基线不对称。
- `showQuote()` 在 `index.html:1512-1517` 将中文译文放入超大主引文，将英文原文、来源和解读分层展示；因此可以只调整主引文的展示标点和断行，而不修改源 Markdown 或全文正文。
- 适用的设计研究共识是：显示标题通常控制在两行内；较长引文属于 statement，允许 1–3 个语义行组；正文自然换行；标签和元信息在空间足够时单行显示。外部 skill 中的 React、Tailwind、移动端和外部字体要求不适用于本项目。
- 当前 `tests/desktop-smoke.spec.js` 共 6 项测试，其中图片查看器测试固定创建 `390×844` 视口；`npm test` 仍须保留并执行这项历史回归，但它不属于本任务的移动端设计或验收，新增排版检查只使用桌面视口。
- 用户进一步确认：1920×1080 是标准桌面版式；1440×900 与 1024×900 只做列宽/字号降级，不因“刚好放得下”重新选择引文行组。相同引文在三个桌面视口保持同一组语义断点。

## Requirements

1. 以共享排版规则解决同类问题：标题断行边界、中文字符换行策略、显示字号/行高、标题容器可用宽度和正文最大行宽必须有一致的设计原则。
2. 预设的中文标题行不得在 1920×1080、1440×900 和 1024×900 桌面视口中被拆成孤立单字；桌面列宽变化时必须采用可读的桌面布局降级，而不是隐藏、删文案或水平溢出。
3. 同一标题层级在首页模块和全文页使用可解释的字号、字重、字距和行高层级；局部例外必须有明确的结构原因。
4. 保留所有现有中文文案、英文 kicker、统计信息、章节定位、搜索目标和页面交互，不通过删减文字解决排版问题。
5. 只修改排版所需的 `index.html`、`notes.html`、必要的桌面回归测试和产品设计记录；不修改 `content/`、`scripts/build-content.cjs`、图片或生成数据。
6. 继续使用现有动效和 `prefers-reduced-motion` 行为，不新增框架、字体 CDN 或运行时依赖。
7. 引文装饰必须使用语义明确的成对开闭引号，主引文的断行和标点处理必须服务于展示层级，不得用旋转同一字形或全局删标点解决视觉问题；标题 1–2 行、主引文 1–3 个平衡语义行组只是设计目标，完整内容和可读字号优先，不得为凑行数裁切、隐藏、省略号或过度缩小。
8. 文字层级必须区分展示标题、引文主显示、标签/元信息、正文、列表和表格；不把所有文字强制压成一行，也不通过删减原文获得所谓整齐。
9. 首页引文主显示采用局部、可审计的展示层去标点：省略装饰性逗号和句号并保留语义分句；`content/`、`archive.js`、`notes.html` 完整正文、英文原文和搜索源文本保留原标点。
10. 以 1920×1080 确定引文的基准语义行组；1440×900 与 1024×900 必须保留相同的行组顺序和分段，不得因为容器变化自动折叠为另一种行数。

## Out of Scope

- 不重写原始笔记内容，不改变章节结构、搜索契约或生成数据。
- 不重做图片、颜色主题、模块信息架构、动画交互或 Cloudflare 部署链路。
- 不把单个截图修复成不可复用的定位补丁。
- 不修改源 Markdown 或完整全文中的标点语义；任何去标点只能发生在明确的展示层映射中，并保留可访问/全文原文。
- 本任务只做桌面端文字排版：正式验收视口为 1920×1080 与 1440×900，辅助桌面边界为 1024×900。移动端（手机/平板）不新增布局、不做移动端视觉调整、不新增移动端截图或验收；现有测试套件中的 1 项 `390×844` 图片查看器回归继续保留，但不构成本任务的移动端交付。

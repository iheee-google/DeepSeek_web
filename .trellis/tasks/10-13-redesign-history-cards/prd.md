# 重设计史实对照模块

## Goal

重做首页“史实对照”模块，使两组完整原文在桌面端拥有清晰的证据层级和自然高度，消除长卡与短卡并列时产生的大面积空白，同时保留所有历史事实与鉴赏边界内容。

## Confirmed Facts

- 用户截图对应首页 `index.html` 的 `#history` / `#historyGrid`，不是时间轴。
- `scripts/build-content.cjs` 从原 Markdown 第九章生成两条 `archive.history`，当前没有图片字段；首页只渲染文字。
- `history-01`《标志性事件的史实对照》包含 4 条完整史实证据，涉及阿巴拉钦峰会、理发馆刺杀/莫·格林、哈瓦那政权更替、安布罗西亚诺银行案。
- `history-02`《鉴赏时需理清的三个界限》包含 3 条完整鉴赏边界，涉及约翰尼·芳丹/弗兰克·辛纳屈、麦克·柯里昂原型、第三部教皇情节。
- 两条记录内容量不同；当前桌面 CSS 使用两列网格，卡片自然高度不同，导致右卡底部留下明显空白。历史卡仍有旧的 `min-height` 基线，但当前覆盖样式已取消固定高度。
- `docs/design-v2.md` 要求历史勘误保留电影事件与现实原型对照内容，使用证据卡呈现；原 Markdown 是唯一内容源。

## User Outcome

用户应能一眼区分“电影借来的现实”和“电影创作的边界”，看到完整正文，并且每组证据都像独立的档案记录，而不是一个被另一张卡撑空的并列盒子。

## In Scope

- 重做 `#history` 标题说明和 `#historyGrid` 的桌面信息层级。
- 保留两条 `archive.history` 的完整 `html`、标题、稳定 ID 和全文链接。
- 解决两条记录内容量不同造成的空白、底部不齐和阅读节奏问题。
- 保留无图片原则，不新增图片、不引入兜底剧照。
- 增加桌面 Playwright 回归和 1440×900 截图复核。

## Out of Scope

- 不修改 `content/godfather-trilogy-notes-v4.md` 的内容语义或顺序。
- 不修改 `notes.html` 全文阅读布局、时间轴、规则区、图片查看器或其他首页模块。
- 不新增框架、依赖、外部运行时或图片资源。
- 本任务以桌面端视觉为目标，不新增移动端设计或移动端功能。

## Design Constraint

参考 Transitions.dev 的 card resize / panel reveal、Rare UI 的档案导航层级和 shadcn/ui 的 Accordion/Tabs 状态边界时，只提炼信息层级和状态表达，不复制代码、不引入运行时依赖。普通模式的进入、悬停/聚焦和离开状态需要有反馈；`prefers-reduced-motion` 下立即切换。

## Confirmed UX Decision

采用**上下两条全宽档案证据带**。每条记录使用左侧紧凑编号/类别/标题与右侧受控行宽的完整证据正文，记录垂直排列、各自自然高度，不再让一张卡匹配另一张卡的高度。两组内容同时可见，适合比较四条史实证据与三条鉴赏边界；代价是模块纵向变长。

## Acceptance Criteria

- [x] 两条历史记录都完整可见，正文不删减、不改写，且各自稳定 ID 和全文链接保持有效。
- [x] 桌面端不再出现由相邻卡片高度差产生的大面积空白；每条记录的边界、编号、标签、标题和正文层级清晰。
- [x] 历史模块不渲染任何图片，页面不新增图片资源或图片映射。
- [x] 进入、聚焦/悬停、退出状态有明确反馈；`prefers-reduced-motion` 下内容仍立即可见。
- [x] 现有搜索、章节跳转、生成数据链路和其他首页模块不回归。
- [x] `npm run build:content`、`npm test`、语法检查、`git diff --check` 和桌面视觉截图复核通过；不将窄屏检查表述为移动端验收。

## Open Questions

None blocking. 用户已选择上下全宽证据带；仍需审批完整设计和实施计划后才能进入代码修改。

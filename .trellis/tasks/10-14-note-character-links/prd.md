# 全文角色名称标注与跳转

## Goal

在独立全文页 `notes.html` 中识别原文里出现的角色名称，为可确认的名称增加清晰、可访问的标注；用户点击后先看到确认弹窗，确认后进入首页人物模块并自动打开对应的现有角色卡片介绍。

## User value

用户阅读完整笔记时，可以从正文中的角色名称直接进入人物档案，而不需要先离开全文、手动寻找人物模块或重新搜索角色。

## Confirmed repository facts

- `notes.html` 在运行时将 `archive.sections[].html` 注入 `#noteContent`（当前脚本约在 `notes.html:230`），之后再建立目录、reveal 和 hash 跳转。
- `scripts/build-content.cjs:125` 的 `parsePeople()` 从原始 Markdown 角色标题生成 44 条人物数据；当前数据使用 `person-01` 至 `person-44`，并提供 `title`、`html`、`text` 和全文目标。
- `index.html` 已有 44 张人物卡片、`morphPerson()` 角色介绍弹窗和完整正文链接；`bindCharacterCards()` 负责卡片键盘/点击行为。当前首页没有根据 URL 参数自动打开指定人物卡片的入口。
- 角色标题包含中文名、英文名、别名、称谓和复合标题。`person-27` 的一张卡同时介绍维克多·斯特拉奇和卡迈恩·库尼奥；泛称、姓氏和单字简称存在误匹配风险。
- 正文中的名称出现次数和形式不完全等于人物标题。不能用任意短字符串、姓氏或演员姓名进行全文替换。
- 当前预览服务仅公开 `index.html`、`notes.html` 和 `assets/`；新功能不能扩大公开边界。

## Research findings

- shadcn/ui 的 Hover Card 用于 hover/focus 预览链接背后的内容，适合轻量预览，不适合本功能的明确跳转确认。
- shadcn/ui 的 Dialog 由标题、说明、内容和操作组成；Alert Dialog 用于需要用户回应的中断场景，提供取消和继续动作。这里只借鉴状态和可访问结构，不引入 React/Radix 依赖。
- Transitions.dev 的 Panel Reveal 使用 `transform`、`opacity` 和 `blur` 表达开关状态，并在 `prefers-reduced-motion` 下关闭过渡；适合本项目已有的原生 CSS 动效约束。
- beUI 的 Popover/Tooltip 展示了触发器、键盘焦点和 reduced-motion 的组合；Beautiful UI、Rare UI 等未发现可直接复用的“全文人物名到人物卡片”案例。只采用公开交互原则，不复制实现或增加运行时依赖。

## Confirmed product decision

- 角色名称点击并在弹窗中确认后，同标签页进入 `index.html`，自动滚动到人物模块并打开对应的现有角色卡片；不复制角色卡片到全文页，也不默认打开新标签页。
- 标注所有可唯一归属的完整中文名、英文名和明确别名；跳过泛称、姓氏和歧义短称。角色名出现于正文时全量标注，不限制为每章首次出现。
- 取消、关闭或 Escape 不离开全文，阅读位置和焦点恢复到触发的角色名称。

## Requirements

1. 在 `notes.html` 的完整正文中对受控人物名称做展示层标注，保留原始可见字符、标点、章节结构、搜索文本和稳定定位。
2. 角色名称映射必须与现有 44 条人物数据和稳定人物 ID 对齐；别名映射需要能发现标题变更或未知名称，不能静默跳到错误人物。`person-27` 的两个人名必须明确指向其共享人物介绍。
3. 标注只作用于正文语义文本，不嵌套已有链接、图片替代文字、代码或控件，不改变原文 HTML 的其他语义。
4. 标注名称使用语义交互控件。激活后显示确认弹窗，弹窗说明人物名称和将要前往的人物介绍，提供明确的取消/关闭与确认操作；支持鼠标、键盘焦点、Enter/Space、Escape 和焦点恢复。
5. 确认后首页根据已验证的人物 ID 打开对应人物卡片；无效或未知的 URL 人物参数必须安全忽略，不得抛出脚本错误或打开错误卡片。
6. 弹窗与跳转保留现有 family–power 视觉语言、Lucide 图标、进入/激活/退出反馈和 `prefers-reduced-motion` 即时状态；不引入外部依赖。
7. 保留现有 URL、目录/hash 定位、正文内容、搜索索引、人物卡片数据、图片、部署边界和全文阅读结构。

## Out of scope

- 不改原始 Markdown 的文字内容、标点、顺序或人物介绍正文。
- 不把所有姓氏、泛称（如“教父”）、演员姓名或无法唯一归属的短称强行标注。
- 不重做人物卡片、全文页面布局、搜索系统或 Cloudflare 发布配置；允许生成器为现有人物数据增加受控的角色名称映射元数据。
- 不增加移动端专门设计；既有窄视口检查只用于防回归，不构成移动端交付。
- 不复制参考站点代码、不安装 React/Radix 或外部 CDN 依赖。

## Acceptance criteria

- [ ] 正文中所有纳入映射的角色名称都有可见标注，标注文本与原文字符完全一致；未纳入的歧义短称保持普通文本。
- [ ] 44 条人物记录和受控别名映射通过构建校验；英文词边界、别名重叠、同名反例、未知人物 ID 和 `person-27` 共享卡映射均有失败或明确验证，不静默错跳。
- [ ] 标注前后 `#noteContent` 的完整 `textContent`、已有链接属性、heading/block ID 和未标注歧义名称保持不变；重复初始化不会再次包裹名称，跨内联节点的名称不会破坏原结构。
- [ ] 点击或键盘激活标注后，确认弹窗显示正确人物；取消、关闭、Escape 和 Tab 循环行为正确，背景 inert/滚动锁恢复，焦点回到原标注，阅读位置不改变。
- [ ] 确认后进入首页，等待初始化和 reveal 稳定后自动滚动到人物模块并打开正确的现有角色卡片；只移除一次性 `person` 参数并保留其他 query，卡片的全文链接仍指向对应的 `notes.html#chapter-06-part-*`。
- [ ] 正常动效和 `prefers-reduced-motion` 下，弹窗进入/退出、跨页跳转和卡片打开均有稳定最终状态，无竞态、重复弹窗或 page error。
- [ ] 现有桌面 Playwright 回归、角色卡片交互、全文 hash/目录定位、搜索和历史 390px 图片查看器回归继续通过；新增测试覆盖至少一个中文名、一个英文/别名、`person-27` 两人共享卡、取消/Escape、确认跳转和无效参数。
- [ ] 生产构建、内容生成、JavaScript 语法、预览白名单和 `git diff --check` 通过；不修改内容源以外的未授权资产或部署文件。

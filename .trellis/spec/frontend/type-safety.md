# Type Safety

## Applicability

The runtime is JavaScript, not TypeScript. There are no declaration files, generated TypeScript types, Zod/Yup schemas, or generic utility types. Type safety is established by the content compiler's object shapes, stable ID rules, escaping boundaries, and browser regression tests.

Do not add TypeScript terminology or pretend that a JavaScript object is statically checked. If a new data contract is introduced, document its producer, consumer, required fields, and a test for invalid or missing targets.

## Data Contracts

`scripts/build-content.cjs` is the contract owner for `assets/data/archive.js`. Important record families include:

- chapters/sections: `id`, `title`, `html`, `text`, `blocks`, and heading metadata;
- rules/history/motifs: `id`, `title`, rendered `html`, plain `text`, search `blocks`, and source `target` where applicable;
- people: `id`, `title`, `actor`, `group`, `image`, rendered `html`, `text`, `blocks`, and a full-text `target`;
- timeline: `id`, `era`, `work`, and `event`;
- quotes: `id`, `group`, `original`, `translation`, `source`, and `explanation`;
- search records: `kind`, `id`, `target`, `title`, and searchable `text`.

When changing a record, update the compiler, every route consumer, and the relevant browser assertions in the same task. Do not silently make a required field optional in one renderer.

## Stable IDs and Validation

The Markdown renderer assigns IDs to headings and content blocks (`<p>`, `<blockquote>`, `<table>`, and list items). These IDs are used by directory links, Rail TOC links, search, timeline/person/motif jumps, and the reader's full-text link. Preserve uniqueness and deterministic ordering.

Tests should assert that important targets exist exactly once. `tests/desktop-smoke.spec.js` already checks duplicate IDs, directory target validity, search target validity, and cross-route source positioning. Add similar assertions for any new target kind.

## Escaping and HTML Boundaries

- Plain values interpolated into templates go through the route's `escapeHtml` path.
- Rich HTML is generated by the controlled MarkdownIt renderer in `scripts/build-content.cjs`; do not bypass it with arbitrary HTML strings.
- `toAssetPath` and the renderer own conversion from source-relative image paths to `assets/...` paths.
- `resolvePublicPath` treats malformed URLs, traversal segments, dot-prefixed paths, and non-allowlisted paths as invalid; preserve that fail-closed behavior.

Use optional chaining only when a node or field is intentionally route-specific. Do not add `|| ''` fallbacks that turn a missing required target into a silently broken navigation link.

## Common Patterns

Use explicit conversion at boundaries: `Number(...)` for data attributes used as indexes, `String(...).padStart(...)` for display IDs, and normalized text/IDs in the compiler. Keep `plainText` and `normalizeKey` in the compiler where they can be reused by all generated records.

When a browser API can reject (fullscreen, URL decoding, file resolution), handle the known failure at that boundary and expose a visible fallback or 404. Do not catch every error around an entire module.

## Forbidden Patterns

- Hand-editing `assets/data/archive.js` to fix a missing field.
- Using array positions as permanent hash IDs.
- Interpolating titles, search text, or asset paths into HTML without escaping/validation.
- Casting or assuming a record field exists without updating the compiler and test contract.
- Suppressing a broken target with a generic fallback that prevents the failure from being observable.
- Expanding the preview allowlist or path resolver without a regression for traversal and source-file exposure.

# Directory Structure

## Repository Shape

This is a single-package, framework-free frontend. There is no `src/` tree and no build bundler for the pages.

```text
.
├── index.html                         # archive-explorer route and inline page behavior
├── notes.html                         # complete source-note route and Rail TOC
├── content/
│   └── godfather-trilogy-notes-v4.md  # note authoring source
├── assets/
│   ├── data/archive.js                # generated archive data; do not hand-edit
│   ├── css/image-viewer.css           # shared image viewer styles
│   ├── js/image-viewer.js             # shared image viewer behavior
│   ├── vendor/lucide.min.js           # local icon runtime
│   ├── posters/                       # trilogy posters
│   ├── portraits/                     # people imagery
│   └── scenes/                        # scene imagery
├── scripts/
│   ├── build-content.cjs              # Markdown compiler and stable-ID generator
│   └── serve-preview.cjs              # allowlisted local preview server
├── tests/desktop-smoke.spec.js        # Playwright behavior and security regression
├── docs/design-v2.md                  # product design and interaction direction
├── package.json                        # build, preview, and test commands
├── playwright.config.js               # Playwright project and preview startup
└── .trellis/
    ├── spec/frontend/                 # durable coding guidance
    ├── tasks/                         # task plans and acceptance criteria
    └── workspace/                      # developer/session journal
```

## Ownership Boundaries

- **Content**: write note prose and Markdown image references under `content/`. The compiler owns HTML conversion, asset prefixing, stable IDs, extracted module data, and search records.
- **Runtime pages**: keep route-specific markup and browser behavior in the matching HTML file. Shared image-viewer behavior belongs in `assets/js/image-viewer.js` and `assets/css/image-viewer.css`.
- **Generated output**: `assets/data/archive.js` is regenerated by `scripts/build-content.cjs`. A change to the source note must be followed by `npm run build:content`.
- **Public files**: `scripts/serve-preview.cjs` exposes only `index.html`, `notes.html`, and paths under `assets/`. Do not broaden this allowlist to make development easier.
- **Tests**: add browser behavior and route/security assertions in `tests/desktop-smoke.spec.js`; configure viewport and preview behavior in `playwright.config.js`.
- **Product documentation**: keep visual/product decisions in `docs/`. Link or summarize stable implementation rules in `.trellis/spec/`, rather than duplicating the document.

## Naming and ID Conventions

- Use lowercase, hyphen-separated filenames for assets and scripts (`image-viewer.js`, `build-content.cjs`).
- Use stable semantic DOM IDs for navigation and test targets (`chapter-03-heading`, `readerPanel`, `rule-01`).
- Use `data-*` attributes for generated relationships and behavior (`data-person`, `data-group`, `data-note-block`, `data-note-jump`, `data-search-index`).
- Generate IDs in one place: `scripts/build-content.cjs` assigns chapter, heading, block, person, rule, history, quote, timeline, and motif IDs.
- Keep generated archive object keys aligned with the renderer that consumes them; do not create a second ad-hoc content format in an HTML file.

## Asset Ownership and Selection

Keep local image files when they are explicitly referenced by the source Markdown or by a documented, semantic UI mapping. The complete-note route depends on the source-note images being local so the original material remains intact and previewable without the user's Windows source path.

Homepage modules must not use a rotating or generic image fallback merely to fill a card. If an image does not correspond to the module's content, render the module without an image. Before adding or replacing an asset, search the Markdown and route mappings, then verify the rendered aspect ratio and semantic match. Unreferenced decorative copies should not be added to the repository.

## Common Mistakes

- Adding a new source image by editing `assets/data/archive.js` instead of the Markdown source and compiler.
- Using a generic scene as a cover for an unrelated rule/history/person module.
- Reusing a visible DOM `id` for a modal copy or a generated heading; duplicate IDs break hash jumps and TOC state.
- Placing source files, the Markdown note, or `.git` under the public preview root.
- Creating a new `src/` abstraction or framework layer for a behavior that belongs in an existing route module or shared viewer.
